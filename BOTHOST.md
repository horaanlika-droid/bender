# Деплой на BotHost + Telegram

Лендинг, морда и бот живут в `app.js` (Node 18+, **ноль зависимостей**) + `public/`.
BotHost клонирует репозиторий и поднимает `app.js` — и лендинг, и Mini App, и бота.

## Что где

| Файл | Роль |
|---|---|
| `app.js` | HTTP-статика из `public/`, `/health`, `/api/face`, `/api/recall`, Telegram-бот (long polling) |
| `lib/lore.js`, `lib/brain.js` | память и мозг на Node: те же `brain/lore/*.md`, что у python-мозга |
| `public/index.html` | **морда** — глаза и рот для планшета в голове (управляется из бота) |
| `public/about.html` | лендинг проекта |
| `public/manifest.webmanifest`, `public/icon.svg` | чтобы планшет открывал морду как приложение (standalone) |
| `public/audio/` | записанный голос Бендера: коронные фразы канона + `manifest.json` (морда ищет запись по тексту, остальное — синтез планшета) |
| `package.json` | `npm start` → `node app.js`, `npm test` → тесты Node-слоя |
| `Dockerfile` | явная сборка для BotHost (рабочая папка вне `/app`, как в их FAQ); копирует `lib/`, `brain/`, `public/` |

## Что вписать: две переменные

Хозяину нужно вписать в панели BotHost **ровно две** переменные:

| Переменная | Что вписать | Зачем |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather, вида `123456789:AA...` | бот: `/start`, кнопки Mini App, команды хозяина |
| `ADMIN_ID` | **свой chat id** — число, например `777001` | без него выключены `/say` и `/expr`: только хозяин говорит через морду |

Этого достаточно для всего: лендинг, морда, бот, управление мордой из чата.

Дополнительно, по желанию (можно не заполнять):

| Переменная | Зачем | Если не задана |
|---|---|---|
| `WEBAPP_URL` | публичный адрес, напр. `https://bender.bothost.ru` — для кнопок Mini App и `og:image` | адрес выводится из Host первого запроса |
| `TG_BOT_URL` | ссылка на бота, напр. `https://t.me/bender_prototype_bot` — кнопка «Написать боту» на лендинге | кнопка на лендинге скрыта |
| `PORT` | порт HTTP | задаёт платформа |
| `LLM_URL` | адрес живой модели, напр. `http://127.0.0.1:11434` (Ollama) или `https://…/v1` | отвечает заглушка на правилах, память всё равно работает |
| `LLM_MODEL`, `LLM_KIND`, `LLM_API_KEY`, `LLM_TIMEOUT` | уточнения к `LLM_URL` (модель, `ollama`/`openai`, ключ, таймаут в секундах) | разумные умолчания |

Без `LLM_URL` Бендер всё равно отвечает по канону: память (`lib/lore.js`) ищет куски в
`brain/lore/*.md`, а `lib/brain.js` собирает ответ на правилах. `LLM_URL` лишь заменяет
формулировки на живую модель, промпт с памятью уходит ей целиком.

## Как узнать ADMIN_ID (полминуты)

1. Задеплоить проект (шаг 2) — бот уже работает и без `ADMIN_ID`: `/start`, `/help`, `/status`, `/id`.
2. Написать боту в Telegram: `/id` → он ответит `Твой chat id: 777001.`
3. В панели BotHost → переменные окружения → добавить `ADMIN_ID` = это число (и `BOT_TOKEN`, если ещё нет).
4. Перезапустить бота. В чат придёт: `🤖 Я в сети, старина. Морда: https://...` — значит, оба значения прочитаны.
5. Проверка админки: `/say Я Бендер, пожалуйста, вставьте балку.` — планшет с открытой мордой скажет это вслух.

Секретов в Git нет и не будет: и токен, и id живут только в переменных BotHost.

## Команды бота

| Команда | Кому | Что делает |
|---|---|---|
| `/start`, `/help` | всем | рассказ + две кнопки Mini App: «Морда» и «О проекте» |
| `/status` | всем | статус сборки, касса, виден ли админ и морда |
| `/id` | всем | chat id и признак админа — как узнать `ADMIN_ID` |
| `/ping` | всем | жив ли бот, аптайм, размер очереди морды |
| `/say текст` | **хозяину** | морда на планшете скажет этот текст вслух (до 400 символов) |
| `/expr happy\|angry\|surprised\|idle` | **хозяину** | выражение морды |
| `/eyes on [минуты]` | **хозяину** | включает камеру и микрофон планшета (по умолчанию 15 мин, максимум 60); бот даёт кнопку «Открыть глаза на планшете» |
| `/eyes off`, `/eyes status` | **хозяину** | выключить / узнать, включено ли и сколько кадров пришло |
| `/look` | **хозяину** | присылает последний кадр камеры фото в чат |
| `/heard` | **хозяину** | последние пять фраз, которые морда услышала |

Глаза и уши включаются **только** по токену из кнопки `/eyes on`. Открыть морду по адресу без токена
можно, но камера и микрофон в таком случае молчат. Кадры хранятся в `var/eyes/latest.jpg` (папка в `.gitignore`),
фразы — в памяти процесса; на диск ничего не пишется, кроме последнего кадра. Сессия гаснет сама по времени.

Чужим `/say` и `/expr` бот не выполнит: рот морды слушает только `ADMIN_ID`.

## Как хозяин говорит через планшет

```
Telegram: /say Хлещи сильнее, профессор!
     │  bot (app.js, long polling)
     ▼
очередь команд в памяти ──GET /api/face?since=N──►  морда на iPad (опрос раз в 2 c)
                                                    speechSynthesis: говорит, рот шевелится
```

- Планшет сам опрашивает сервер — до iPad не нужно «дозваниваться», он может жить в любой сети.
- Индикатор `бот` в правом верхнем углу морды зелёный = связь с сервером есть.
- Команду старше 30 секунд морда не проигрывает: выключенный планшет не начнёт говорить сам.
- Очередь держит 50 последних команд и умирает вместе с процессом — это пульт, а не архив.

## Шаг 1. Бот в @BotFather

1. `/newbot` → имя и username (например `bender_prototype_bot`) → **токен сохранить** (в Git не писать,
   он пойдёт в переменную `BOT_TOKEN`).
2. `/setmenubutton` → кнопка меню «Морда» → URL: `https://<ваш-домен>/`
   (после шага 2, когда домен известен). Menu Button — самая удобная точка входа на iPad.

## Шаг 2. Проект на BotHost

1. Регистрация на [bothost.ru](https://bothost.ru/) → «Создать бота».
2. Платформа: **Telegram**, тип: **Node.js**, Git URL: `https://github.com/horaanlika-droid/bender`,
   ветка с работой (по умолчанию `main`).
3. Bot Token: вставить токен от BotFather (он же можно задать как `BOT_TOKEN`).
4. Домен: поддомен `bothost.ru` (например `bender.bothost.ru`) — HTTPS выпускается автоматически.
   При желании записать его в `WEBAPP_URL`.
5. Деплой → в логах должно быть:
   `✅ Лендинг на порту 3000 (public: ...)`, `🤖 Telegram-бот: токен найден...`, `👑 Админ (ADMIN_ID): ...`.
6. Проверка: `https://<домен>/health` → `{"ok":true,"bot":true,"admin":true,...}`.

## Шаг 3. Связка с Telegram

- Menu Button (шаг 1) открывает морду прямо в чате.
- Бот отвечает на `/start`, `/help`, `/status`, `/id`, `/ping` и даёт две Mini App-кнопки.
- Хозяин: `/say текст` — морда говорит; `/expr angry` — морда злится.
- Автообновление: в панели BotHost есть Webhook URL → GitHub: Settings → Webhooks → Add webhook
  (JSON). Дальше деплой идёт при каждом пуше.

## Локальная проверка

```
node app.js                                   # http://localhost:3000 — морда, /about.html — лендинг
BOT_TOKEN=123:test ADMIN_ID=777001 node app.js  # + бот; /id покажет id, /say говорит через морду
curl localhost:3000/health                    # {"ok":true,"bot":true,"admin":true,...}
npm test                                      # тесты Node-слоя (бот, /api/face, статика)
```

`TG_API_BASE` — только для тестов: подменяет `https://api.telegram.org` на локальный mock,
чтобы прогонять путь «хозяин → бот → морда» без настоящего Telegram.

## Подводные камни BotHost (учтены)

- Сборка с `Dockerfile` → рабочая папка `/usr/src/app`, **не** `/app`: на части нод `/app`
  монтируется из Git и затирает артефакты сборки (их справочник ошибок).
- В репозитории живут и Python-мозги (`brain/`), и витрина (`app.js` в корне). Для BotHost
  релевантен только Node-слой; `Dockerfile` копирует лишь `app.js` + `public/` + `package.json`.
- `requirements.txt` в корне не нужен: BotHost ставит его, если находит, и это ломает сборку
  не-Python проектов — не добавлять.
- Long polling (`getUpdates`) не требует webhook-URL бота — работает сразу после деплоя.
- Если задан `ADMIN_ID`, но пуст `BOT_TOKEN` — в логах предупреждение: команды хозяина некуда слать.
